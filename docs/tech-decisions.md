# Technical Decisions

Technical choices made by the development team, one line per decision, newest first. Product decisions are in [decision-log.md](decision-log.md).

| Date | Decision | Reason | Alternatives considered |
| --- | --- | --- | --- |
| 2026-10-17 | The form uses the browser's native date field; the tablet must be set to Spanish so it shows dd/mm/aaaa. Dates our own code displays are always formatted dd/mm/yyyy. | Native touch calendar with no extra code; the date is rarely changed (defaults to today). | Our own dd/mm/yyyy date control, the same on every device. |
| 2026-10-17 | Migrations are applied by pasting them into the Supabase SQL Editor. | One database and one developer; avoids installing and linking the Supabase CLI during the first sprint. | Supabase CLI (`supabase db push`), to revisit if a second environment (e.g. testing) is added. |
| 2026-10-17 | Entries are saved through a database function (`register_entry`, security definer) called with `rpc`; the browser cannot read, change or delete entries directly. | An entry and its anillados are saved together or not at all (one transaction), and the public key cannot be used to read or erase records. | Two direct inserts from the browser (`entries`, then `entry_anillados`) with RLS insert policies. |
| 2026-10-17 | Entries reference departments by id (`areas` table), and anillados by size (`anillado_sizes` table). Departments are hidden with `active = false`, never deleted. | Renaming a department does not break old entries; old reports keep working when a department is removed. | Storing the department name as text in each entry. |
| 2026-10-17 | Vitest for unit tests. | Reuses the Vite configuration, so TypeScript tests run with no extra setup. | Jest (needs its own TypeScript transform). |
| 2026-10-17 | oxlint as the linter, as generated by the Vite template. | Template default, very fast, almost no configuration. | ESLint (more plugins, slower, more configuration). |
| 2026-10-15 | Money is stored and computed as integer centavos, and formatted as Bs only for display. | Binary floating point cannot represent 0.30 exactly, so sums drift; the product promises zero calculation errors. | Floating-point numbers; Postgres `numeric` everywhere. |
| 2026-10-15 | Every database schema change is a numbered SQL migration in `supabase/migrations/`, committed to git. | The schema can be rebuilt, reviewed and traced, like code. | Editing tables only in the Supabase dashboard. |
| 2026-10-15 | The browser talks to Supabase directly with the public anon key, protected by Row Level Security policies. | No backend server to write, deploy or maintain. Anyone with the URL could insert entries, which is acceptable for the pilot (like an open paper notebook). | A custom API (e.g. Vercel serverless functions) in front of the database. |
| 2026-10-15 | TypeScript instead of JavaScript. | Type errors are caught at build time instead of on the tablet; better editor help. | Plain JavaScript. |
| 2026-10-15 | Vite single-page app instead of Next.js. | No server rendering or SEO needed; fewer concepts to learn for a first web app. | Next.js; Create React App (deprecated). |
